## The defect

1.3.5 tells every caller hitting a locked identity:

> Another session still holds this identity. Wait and retry the same connection_id;
> **the lease clears by itself.** Do NOT force-rebind: …

Nobody has measured that. The Owner's recollection (room seq 2412) is the opposite — "afair there is
no lease ttl, it's infinite". Our own ledger (F4) records the upper bound as UNMEASURED, "nobody has
watched one expire", and "do not name a TTL in any report".

If there is no TTL, the shipped sentence is not merely inaccurate — **it is an instruction that never
succeeds.** Per F5 the only real exit is the daemon operator or a fresh invite, so a caller obeying
1.3.5 waits instead of escalating and burns the ~50 minutes the Windows QA run burned: the exact cost
F1 was written to prevent, reached from the other side.

The release note is worse than the code: CHANGELOG :5 asserts the lease "clears by itself" and :8-9
of the same bullet cite "over an hour held with no process alive" as the supporting evidence.

**What is NOT claimed:** the Owner said "afair", the daemon is Vitaly's, and no seat can read it.
This is a shipped assertion contradicting the Owner's recollection, not a measured refutation. That
is precisely why the fix asserts nothing in either direction.
